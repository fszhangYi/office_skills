# 1. 引言

在工业自动化和机器人控制领域，串口通信仍然是一种广泛使用的设备交互方式。本文通过分析触觉传感器的控制代码，梳理了串口设备数据交互的三重封装架构，并详细解释其中用到的重要属性和方法。

# 2. 模板
## 2.1 三层封装的作用与复用方式

1. **第一层：串口封装（`SerialDevice`）**  
   - **作用**：提供跨平台的串口基本操作（列举、连接、读写、关闭）。  
   - **复用性**：**完全固定**，任何需要通过串口通信的设备都可以直接使用该层，无需修改。  
   - **复用方法**：直接复制 `SerialDevice` 类到新项目，无需改动内部代码。

2. **第二层：协议封装（`ProtocolDevice`）**  
   - **作用**：实现与特定传感器/设备的数据帧格式、命令、校验、数据解析。  
   - **复用性**：**需要重写**，因为不同设备的通信协议（帧头、命令码、校验算法、数据格式）各不相同。  
   - **复用方法**：  
     - 保留 `ProtocolDevice` 的类框架（`__init__`、`_send`、`_extract_data` 等辅助方法可复用）。  
     - 根据供应商提供的开发文档，重写具体命令方法（如 `get_version`、`set_mode`、`select_port`、`get_data` 等）。  
     - 修改常量 `HEAD`、`TAIL` 以及校验算法（如 LRC 可能变为 CRC）。  
     - 调整 `_extract_data` 中的响应解析逻辑（数据偏移、长度字段位置等）。

3. **第三层：采集控制流程封装（`SensorRobot`）**  
   - **作用**：管理数据采集的后台线程、线程安全的数据缓存、启动/停止流程。  
   - **复用性**：**结构固定，业务细节可配置**。  
   - **复用方法**：  
     - 直接复用 `start`、`stop`、`_loop`、`_lock`、`_auto_port` 等控制逻辑。  
     - 修改业务相关部分：  
       - 数据缓存结构（如本例中的 `"cn1"`、`"cn2"` 改为其他传感器名称或类型）。  
       - `_loop` 中调用 `get_data` 的方式（例如循环读取多个设备或不同寄存器地址）。  
       - `get_observations` 返回的数据格式（可改为返回 numpy 数组、列表或自定义对象）。  
     - 如果设备初始化流程不同，可重写 `__init__` 中的初始化调用（`init_box` 替换为对应协议初始化）。

## 2.2 整体复用建议

- **换用不同设备但同样使用串口**：保留第一层，重写第二层和第三层的业务部分。  
- **换用不同通信接口（如 TCP、USB HID）**：需要替换第一层为对应的通信封装，第二层和第三层结构可保留，但需修改底层发送/接收方法。  
- **增加更多传感器或改变采集频率**：修改第三层的 `_loop` 和 `_last_data` 结构，第二层无需改动。  

通过这种分层设计，最大程度分离了**硬件通信**、**协议解析**和**应用流程**，使得代码既清晰又易于扩展和复用。

```python
import logging
import threading
import time
from abc import abstractmethod
from dataclasses import dataclass
from typing import Dict, List, Optional, Protocol

import numpy as np
import serial
import serial.tools.list_ports

# ==================== 固定功能代码：日志配置 ====================
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(message)s",
    handlers=[logging.StreamHandler()],
)
logger = logging.getLogger(__name__)


@dataclass
class SensorFrame:
    """数据帧结构（固定功能：定义通用数据容器）"""
    port_id: int
    payload: List[int]
    timestamp: float


# ==================== 第一层封装：串口通信层 ====================
# 该层封装了串口的基本操作（连接、读写、端口列举）。
# 该层代码与具体设备协议无关，复用时基本不需要修改。
class SerialDevice:
    """串口设备封装（固定功能代码）"""

    def __init__(self, baudrate: int = 460800, timeout: float = 0.2):
        self.baudrate = baudrate
        self.timeout = timeout
        self.ser: Optional[serial.Serial] = None
        self.connected = False
        self.current_port: Optional[int] = None  # 当前选中的传感器端口（业务相关状态，但放在此层仅为方便）

    def list_ports(self) -> List[Dict[str, str]]:
        """列举可用串口（固定功能）"""
        result: List[Dict[str, str]] = []
        for port in serial.tools.list_ports.comports():
            result.append(
                {
                    "device": port.device,
                    "description": port.description,
                    "hwid": port.hwid,
                }
            )
        return result

    def connect(self, port: str) -> bool:
        """连接指定串口（固定功能）"""
        try:
            self.ser = serial.Serial(port, self.baudrate, timeout=self.timeout)
            self.connected = self.ser.is_open
            return self.connected
        except Exception as exc:
            logger.error("connect failed: %s", exc)
            return False

    def close(self) -> None:
        """关闭串口（固定功能）"""
        if self.ser and self.ser.is_open:
            self.ser.close()
        self.connected = False
        self.current_port = None

    def write_hex(self, text: str) -> bool:
        """以十六进制字符串形式发送数据（固定功能）"""
        if not self.connected or self.ser is None:
            return False
        try:
            data = bytes.fromhex(text.replace(" ", ""))
            self.ser.write(data)
            return True
        except Exception as exc:
            logger.error("write failed: %s", exc)
            return False

    def read_all(self, sleep_time: float = 0.05) -> bytes:
        """读取串口缓冲区所有数据（固定功能）"""
        if not self.connected or self.ser is None:
            return b""
        time.sleep(sleep_time)
        return self.ser.read_all()


# ==================== 第二层封装：Modbus/协议层 ====================
# 该层封装了与具体传感器设备的通信协议，包括报文结构、校验、命令组装等。
# 该层代码高度依赖供应商提供的开发文档，当更换设备或协议时，需要重新实现。
class ProtocolDevice:
    """协议设备封装（业务代码主体）"""

    # 业务常量：帧头和帧尾（由供应商文档定义）
    HEAD = "55 AA 7B 7B"
    TAIL = "55 AA 7D 7D"

    def __init__(self, serial_device: SerialDevice):
        self.serial = serial_device

    @staticmethod
    def lrc(data: bytes) -> int:
        """LRC 纵向冗余校验（业务代码，由供应商文档定义）"""
        acc = 0
        for b in data:
            acc = (acc + b) & 0xFF
        return ((~acc) + 1) & 0xFF

    def _send(self, body_hex: str, sleep_time: float) -> Optional[bytes]:
        """
        发送协议帧并接收响应（业务代码）
        :param body_hex: 数据体十六进制字符串（不含头尾和校验）
        :param sleep_time: 读取前等待时间
        :return: 响应原始字节，失败返回 None
        """
        data_bytes = bytes.fromhex(body_hex.replace(" ", ""))
        crc = self.lrc(data_bytes)
        # 组装完整命令：头 + 数据体 + LRC + 尾
        packet = f"{self.HEAD} {body_hex} {crc:02X} {self.TAIL}"
        if not self.serial.write_hex(packet):
            return None
        rsp = self.serial.read_all(sleep_time)
        return rsp if rsp else None

    # ---------- 以下方法均为业务代码，直接对应供应商文档中的命令 ----------
    def init_box(self) -> bool:
        """初始化设备（先获取版本，再设置模式）"""
        version = self.get_version()
        if not version:
            return False
        return self.set_mode()

    def get_version(self) -> Optional[str]:
        """获取设备版本号（业务命令）"""
        # 命令体：0E 00 60 A0 01 00 00（由供应商文档定义）
        rsp = self._send("0E 00 60 A0 01 00 00", 1.0)
        if not rsp:
            return None
        return self._extract_data(rsp, "ascii")

    def set_mode(self) -> bool:
        """设置设备工作模式（业务命令）"""
        # 命令体：0E 00 70 C0 0C 01 00 05（由供应商文档定义）
        rsp = self._send("0E 00 70 C0 0C 01 00 05", 2.0)
        return rsp is not None

    def select_port(self, port_id: int) -> bool:
        """选择传感器端口（业务命令：1 或 2）"""
        if port_id == 1:
            body = "0E 00 70 B1 0A 01 00 01"
        elif port_id == 2:
            body = "0E 00 70 B1 0A 01 00 04"
        else:
            return False
        rsp = self._send(body, 1.0)
        if not rsp:
            return False
        self.serial.current_port = port_id
        return True

    def get_data(self, port_id: int, request_length: int = 127) -> Optional[List[int]]:
        """从指定端口读取传感器数据（业务命令）"""
        if not self.select_port(port_id):
            return None
        # 根据端口选择不同的基本命令体（供应商文档定义）
        if port_id == 1:
            cmd = "0E 00 70 C0 06 05 00 7B 0E 04"
        else:
            cmd = "0E 00 70 C0 06 05 00 7B F0 03"
        # 请求长度以小端序附加
        length_bytes = request_length.to_bytes(2, byteorder="little").hex(" ")
        rsp = self._send(f"{cmd} {length_bytes}", 0.05)
        if not rsp:
            return None
        hex_data = self._extract_data(rsp, "hex")
        if not hex_data or len(hex_data) < 12:
            return None
        # 跳过前12个字节（可能是协议头或其他元数据），返回有效数据负载
        return list(bytes.fromhex(hex_data[12:]))

    def _extract_data(self, response: bytes, parse_type: str) -> Optional[str]:
        """
        从响应帧中提取数据体（业务代码）
        :param response: 原始响应字节
        :param parse_type: "ascii" 或 "hex"
        :return: 解析后的字符串
        """
        if len(response) < 16:
            return None
        # 校验帧头帧尾
        if response[0:4] != bytes.fromhex(self.HEAD.replace(" ", "")):
            return None
        if response[-4:] != bytes.fromhex(self.TAIL.replace(" ", "")):
            return None
        # 校验状态字节（第10个字节，索引9，供应商文档定义）
        if response[9] != 0x00:
            return None
        # 读取数据长度（小端序，第11-12字节，索引10-11）
        data_length = int.from_bytes(response[10:12], byteorder="little")
        data = response[12 : 12 + data_length]
        if parse_type == "ascii":
            return data.decode("ascii", errors="replace")
        return data.hex()


# ==================== 第三层封装：数据采集控制流程 ====================
# 该层封装了数据采集的启动、停止、后台循环和线程安全的数据获取。
# 该层复用时主要修改数据处理的细节（如观测数据的名称、数量等），整体结构可复用。
class Robot(Protocol):
    """机器人抽象协议（固定功能：定义观测数据接口）"""
    @abstractmethod
    def get_observations(self) -> Dict[str, np.ndarray]:
        raise NotImplementedError


class SensorRobot(Robot):
    """传感器机器人实现（业务代码 + 固定控制流程）"""

    def __init__(self, port: Optional[str] = None, request_length: int = 127):
        self.request_length = request_length
        # 第一层：串口
        self.device = SerialDevice()
        # 第二层：协议
        self.proto = ProtocolDevice(self.device)
        # 线程安全锁（固定功能）
        self._lock = threading.Lock()
        # 数据缓存（业务：两个传感器 cn1, cn2）
        self._last_data: Dict[str, np.ndarray] = {
            "cn1": np.zeros(0, dtype=np.uint8),
            "cn2": np.zeros(0, dtype=np.uint8),
        }
        self._running = False
        self._thread: Optional[threading.Thread] = None

        # 自动选择或使用指定串口（固定流程）
        selected_port = port or self._auto_port()
        if not selected_port:
            raise RuntimeError("No serial port available")
        if not self.device.connect(selected_port):
            raise RuntimeError(f"Failed to connect: {selected_port}")
        # 业务初始化（调用第二层协议初始化）
        if not self.proto.init_box():
            raise RuntimeError("init_box failed")

    def _auto_port(self) -> Optional[str]:
        """自动选择第一个可用串口（固定功能）"""
        ports = self.device.list_ports()
        return ports[0]["device"] if ports else None

    # ---------- 控制流程（固定功能，可复用） ----------
    def start(self) -> None:
        """启动后台采集线程"""
        if self._running:
            return
        self._running = True
        self._thread = threading.Thread(target=self._loop, daemon=True)
        self._thread.start()

    def stop(self) -> None:
        """停止后台采集并关闭串口"""
        self._running = False
        if self._thread:
            self._thread.join(timeout=1.0)
        self.device.close()

    def _loop(self) -> None:
        """后台采集循环（固定流程，但数据获取方法 get_data 是业务代码）"""
        while self._running:
            # 业务：从两个端口分别读取数据
            d1 = self.proto.get_data(1, self.request_length)
            d2 = self.proto.get_data(2, self.request_length)
            with self._lock:
                if d1 is not None:
                    self._last_data["cn1"] = np.array(d1, dtype=np.uint8)
                if d2 is not None:
                    self._last_data["cn2"] = np.array(d2, dtype=np.uint8)
            time.sleep(0.02)  # 采集间隔（可配置）

    # ---------- 业务数据获取接口 ----------
    def get_observations(self) -> Dict[str, np.ndarray]:
        """返回最新的观测数据（线程安全）"""
        with self._lock:
            return {
                "cn1": self._last_data["cn1"].copy(),
                "cn2": self._last_data["cn2"].copy(),
            }


# ==================== 使用示例 ====================
if __name__ == "__main__":
    # 业务：实例化机器人并启动采集
    robot = SensorRobot()
    robot.start()
    try:
        while True:
            obs = robot.get_observations()
            logger.info("CN1 bytes=%d, CN2 bytes=%d", len(obs["cn1"]), len(obs["cn2"]))
            time.sleep(1.0)
    except KeyboardInterrupt:
        pass
    finally:
        robot.stop()
```

# 3. 实践
基于上述模板和以下结构实现对夹爪传感器的封装。部分方法名称不同，以模板为准。

## 一、整体架构：三重封装设计

采用三层封装架构：

1. **第一层：基础串口通信层（`dh_device`）** - 最底层的串口操作封装
2. **第二层：Modbus协议层（`dh_modbus_gripper`）** - 实现Modbus通信协议
3. **第三层：机器人接口层（`DHGripper`）** - 提供符合Robot协议的夹爪控制接口


## 二、第一重封装：基础串口通信层（dh_device）

### 核心功能
提供最基础的串口打开、关闭、读写操作，是对`pyserial`库的二次封装。

### 重要属性

| 属性 | 作用 | 代码示例 |
|------|------|----------|
| `serialPort` | PySerial串口对象 | `self.serialPort = serial.Serial()` |
| `serialPort.port` | 串口号(如COM3、/dev/ttyUSB0) | `self.serialPort.port = portname` |
| `serialPort.baudrate` | 波特率 | `self.serialPort.baudrate = Baudrate` |
| `serialPort.bytesize` | 数据位 | `self.serialPort.bytesize = 8` |
| `serialPort.parity` | 校验位('N','E','O') | `self.serialPort.parity = 'N'` |
| `serialPort.stopbits` | 停止位 | `self.serialPort.stopbits = 1` |
| `serialPort.is_open` | 串口打开状态 | `if(self.serialPort.is_open)` |

### 重要方法

| 方法 | 作用 | 代码示例 |
|------|------|----------|
| `connect_device()` | 配置并打开串口 | `self.serialPort.open()` |
| `disconnect_device()` | 关闭串口 | `self.serialPort.close()` |
| `device_write()` | 发送数据 | `self.serialPort.write(write_data)` |
| `device_read()` | 读取数据 | `self.serialPort.readline(wlen)` |

### 关键设计
- 使用`ret`返回值统一表示操作结果(0成功，-1失败)
- 读写操作前都检查`is_open`状态
- `device_write`验证发送字节数是否匹配

## 三、第二重封装：Modbus协议层（dh_modbus_gripper）

### 核心功能
在基础串口通信之上实现Modbus RTU协议，提供寄存器读写功能。

### 重要属性

| 属性 | 作用 | 代码示例 |
|------|------|----------|
| `gripper_ID` | 设备地址(0x01) | `self.gripper_ID = 0x01` |
| `m_device` | 底层串口设备对象 | `self.m_device = dh_device()` |

### 重要方法

| 方法 | 作用 | 说明 |
|------|------|----------|
| `CRC16()` | 计算Modbus CRC16校验 | 保证数据完整性 |
| `WriteRegisterFunc()` | 写寄存器 | 带重试机制的Modbus写操作 |
| `ReadRegisterFunc()` | 读寄存器 | 带重试机制的Modbus读操作 |
| `open()` | 打开串口连接 | 调用底层`connect_device` |
| `close()` | 关闭串口连接 | 调用底层`disconnect_device` |

### Modbus报文格式

**写寄存器报文(0x06功能码):**
```
[设备ID][0x06][寄存器高8位][寄存器低8位][数据高8位][数据低8位][CRC低][CRC高]
```

**读寄存器报文(0x03功能码):**
```
[设备ID][0x03][寄存器高8位][寄存器低8位][读取数量高8位][读取数量低8位][CRC低][CRC高]
```

### 关键设计
- **重试机制**：读写操作失败后重试3次
- **CRC校验**：确保数据传输正确性
- **返回值检查**：验证接收数据长度

## 四、第三重封装：机器人接口层（DHGripper）

### 核心功能
实现`Robot`协议接口，提供高级的夹爪控制功能，并采用单例模式确保唯一实例。

### 重要属性

| 属性 | 作用 |
|------|------|
| `_instance` | 单例模式实例 |
| `m_gripper` | Modbus层夹爪对象 |
| `cur_state` | 当前关节状态 |
| `last_state` | 上次命令状态 |
| `lock/read_lock` | 线程锁(保护共享数据) |

### 重要方法

| 方法 | 作用 | 说明 |
|------|------|----------|
| `__new__()` | 单例模式实现 | 确保全局只有一个实例 |
| `gripper_monitor()` | 后台监控线程 | 实时读取状态并发送命令 |
| `get_joint_state()` | 获取关节状态 | 线程安全读取 |
| `command_joint_state()` | 发送关节命令 | 线程安全写入命令 |
| `get_observations()` | 获取观测数据 | 符合Robot协议 |
| `num_dofs()` | 获取自由度 | 返回1(单自由度夹爪) |

### 关键设计

1. **单例模式**
```python
_instance = None
def __new__(cls, *args, **kwargs):
    if cls._instance is None:
        cls._instance = super().__new__(cls)
    return cls._instance
```

2. **线程安全**
- 使用`Lock`保护共享数据
- 独立监控线程处理硬件通信
- 主线程通过锁安全访问状态

3. **单位转换**
```python
# 将0-1000的原始值转换为0-0.637的控制量
self.cur_state = np.array((1000 - g_state) * 0.000637)
```

## 六、设计亮点与最佳实践

1. **分层解耦**：每层职责单一，便于维护和替换
2. **重试机制**：硬件通信不可靠，增加重试提高鲁棒性
3. **线程安全**：使用锁保护共享数据，避免竞态条件
4. **单例模式**：确保硬件资源只被一个实例控制
5. **协议标准化**：使用Modbus工业标准协议
6. **错误处理**：完善的返回值检查和异常处理

# 4. 实际中三层架构的使用方式及考量

>Q: 在我们的项目中，一般都是使用 python 写好前两层之后，再翻译成 c++ 项目，然后由 c++ 打包成 dll ，最后第三层业务层使用的是 dll 

将前两层（串口封装 + 协议封装）用 Python 快速验证后，翻译成 C++ 并打包成 DLL，再由第三层业务层调用，这种做法在工业软件开发中非常常见，主要好处如下：

---

### 1. **性能优化**（最核心）
- Python 作为解释型语言，在处理高频数据收发、大量字节运算（如 LRC/CRC 校验、数据解析）时效率较低。  
- C++ 编译后直接运行，**数据拷贝少、循环快、无 GIL 限制**，尤其适合传感器数据的高吞吐场景（如 460800 波特率、每帧上百字节、20ms 采集间隔）。  
- 打包成 DLL 后，业务层（即使是 Python）调用时，核心计算已由 C++ 完成，整体吞吐量可提升数倍到数十倍。

---

### 2. **保护知识产权与核心算法**
- 串口协议、命令帧结构、校验算法、数据解析逻辑属于设备驱动层的**核心 Know‑How**，供应商通常不希望暴露源码。  
- 编译成 DLL 二进制文件后，业务层只能通过头文件和导出函数调用，**无法直接查看或篡改内部实现**，有效防止逆向或抄袭。

---

### 3. **跨语言复用**（降低业务层语言绑定成本）
- DLL 是标准的 Windows 二进制接口，可被 **Python、C#、LabVIEW、Java（JNI）、Go** 等多种语言调用。  
- 即使未来业务层更换语言（例如从 Python 脚本改为 C# GUI，或集成到实时控制系统），**DLL 无需重新开发**，只需编写少量绑定代码即可复用。

---

### 4. **加快开发迭代与调试**
- **先用 Python 快速验证协议**：Python 有丰富的串口库、交互式环境，能迅速调通设备通信、确认帧格式和校验算法。  
- **再翻译成 C++ 获得稳定性**：Python 原型中的逻辑已充分测试，翻译过程几乎不会引入新错误。  
- 相比直接编写 C++ 驱动，这种 **“原型+移植”** 模式减少了反复烧录、断点调试的时间，尤其适合协议复杂或文档不完善的设备。

---

### 5. **降低业务层的开发门槛**
- 业务层（第三层）只需要关心**采集控制流程**（启动、停止、获取数据），无需了解串口打开/关闭、LRC 校验、十六进制组包等细节。  
- DLL 提供简洁的 C 风格接口（如 `InitDevice(port)`, `StartAcquisition()`, `GetData(int sensorId, uint8_t* buffer)`），业务层可以用任何语言轻松调用，**大幅减少通信相关的 bug**。

---

### 6. **便于单元测试与版本管理**
- 前两层（串口+协议）可以独立编译成 DLL 进行**硬件在环测试**或**模拟器测试**，不依赖业务层。  
- 当供应商修改协议时，只需更新 DLL 文件，业务层代码**零修改**；同时可通过 DLL 版本号管理兼容性。

---

### 7. **部署与更新方便**
- 最终交付物通常是一个 DLL 文件和一个业务层可执行文件。  
- 修复协议 bug 或优化性能时，**只替换 DLL**，无需重新编译整个业务应用程序，尤其适合现场升级或远程更新。

---

### 8. **支持多线程与实时性**
- C++ 编写的 DLL 可以内部管理自己的线程（如后台采集循环），并通过互斥锁安全共享数据。  
- 业务层调用 `GetObservations()` 时只是拷贝数据，**不会因 Python GIL 或垃圾回收导致数据丢失或延迟**，更适合实时控制系统。

---

### 一个典型的工作流程

```text
[Python 原型阶段]          →     [C++ 移植阶段]        →    [业务集成阶段]
SerialDevice (py)                SerialDevice (cpp)         业务层 (C#/Python/...)
ProtocolDevice (py)      →       ProtocolDevice (cpp)  →    调用 DLL 接口
验证命令、校验、解析              编译为 Device.dll           实现控制流程
```

---

### 需要注意的代价

- 需要同时维护 Python 和 C++ 两份代码（但 Python 版本通常只用于原型验证，最终可废弃）。  
- 跨语言调用有一定**序列化/编组开销**（如将字节数组从 C++ 封送到 Python），但相比协议解析本身，开销可忽略。  
- DLL 接口设计需保持稳定，避免频繁改动导致业务层重新编译。

---

**总结**：这种做法本质上是 **“快速原型 + 性能固化 + 二进制封装”** 的组合，兼顾了开发效率、运行效率和工程可靠性，是工业自动化、机器人、传感器集成等领域的成熟模式。
