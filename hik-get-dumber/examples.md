# hik-get-dumber 示例（A→C 抽象）

以下来自一次真实改写链：工程师长调研（A）→ 上级决策骨架（B）→ 总经理交付（C）。  
主题碰巧是具身/VLA，**规则可迁移到任意预研/技术选型报告**。

---

## 体量与信息类型

| | 源稿 A | 交付 C |
| --- | --- | --- |
| 量级 | ~10 章，千行级 | ~4 功能块，百行级 |
| 保留 | 验证结论、路线判断、产线约束 | 同左，且提前 |
| 删除 | 多数据集深挖、HDF5/字段、开源项目导览、课堂故事 | — |
| 新增 | — | 选型对照前置；人天/节拍列；阶段表产品锚点；业务词标题 |

---

## 标题降维

| 偏工程师 | 偏总经理 |
| --- | --- |
| VLA 模型训练数据组成及项目调研 | 具身模型数据组成及装备智能化演进 |
| 按数据模态 / 存储结构 / RLDS schema | 具身数据采集（必要时括号 VLA） |
| 实践案例：蓝色杯子放到托盘 | 删掉；或改成产线工件一句话 |

原则：**对外能说的词做标题；缩写不当主角。**

---

## 决策块前置（必补样例列）

不要把「两条验证线」埋在路线章节末尾。提到原理之后、阶段尺之前（或直接第二节）：

| | 路线 A（前沿/端到端） | 路线 B（工程主路径） |
| --- | --- | --- |
| 过程 | 时间线 + 关键动作（各 2–4 句） | 同左 |
| 结果 | 成功率、是否连续可演示、开放项 | 成功率、样机/下单节点 |
| 代价 | 采集轮次、人周、角色配置 | 程序/采集/训练/测试天数 |
| 优势 | 灵活、换型、适应变化 | 节拍、一致性、部署简单 |

站队句示例（可改写）：

> 在确定节拍与良率优先的工位，走 B；需要快速换型/环境波动大的工位，评估 A，且不替代产线主控。

---

## 阶段尺：从抽象未来 → 可指认落点

| 弱（难拍板） | 强（可开会用） |
| --- | --- |
| L4 = 黑灯工厂/自我修复 | L4 = 特定场景具身；例：移动操作机器人 |
| L5 = 超自适应制造（理论） | L5 = 通用具身；例：通用机器人（远期） |
| 例：智能质检系统 | 例：AI 螺丝机（自动标定/孔位识别）、SOP+LLM 建配方 |

格子里写**能指认的产品或公开对标**，让「我们在哪」可见。

---

## 主张段语气

推荐路径常见句式（机制清楚即可）：

- **不是颠覆替代，而是渐进融合与增强。**
- 底座：高精度运动控制 / 稳定机械 / 执行机构 → 节拍、精度、可靠。
- 局部增强：只在自动化难闭环的痛点引入感知—判断—适应。

对照表维度可复用：核心架构、智能范畴、决策机制、实时与确定性、数据与代价、可靠性、落地应用。

「为何选这条」控制在三条内，例如：

1. 前沿值得盯，但现场主驾尚需时间（实时/确定/安全）
2. 纯前沿方案在节拍与成本上易水土不服
3. 局部模块化 = 微创升级，可分步试错

## 数字优先级

| 优先写进主文 | 默认移出主文 |
| --- | --- |
| 抓取/综合成功率、节拍 s/pcs 或 pcs/s | TRL 等级口头炫耀 |
| 示教 Episode 规模（若支撑「已验证」） | 各开源数据集轨迹条数清单 |
| 人天、轮次、岗位配置 | 训练 loss、backbone 名称长释 |
| 下单/装配/量产时间节点 | 论文链接堆砌 |

---

## Agent 改写时的最短自问

1. 主张是否在前 30% 篇幅出现？
2. 有没有一张表同时回答「谁赢在指标」和「谁贵在代价」？
3. 删掉所有英文缩写后，标题是否仍像给领导看的？
4. 新增的表是否在**组织原文证据**，而不是编造新事实？
